# 设计决策文档（DESIGN_DECISIONS）

> 版本：任务 3（修订版）执行期
> 铁律前提：ECC 一律 RS + 喷泉；每个模块 round-trip 测试；仿真器只读实测 calibration.json；不确定处标「假设」；数值类模块可视化校验；自动检测须带完整性校验并显式报错；设计参数须有推导或实测依据。

每条决策均附「反证条件」：即推翻该决策所需的新证据。

---

## D1. 技术栈：TypeScript 全栈 + PWA，接收端零安装

- **决策**：发送端 Web（Vite+React），接收端手机浏览器 `getUserMedia`；codec 为纯 TS、零 DOM，Node/浏览器双跑。
- **依据**：用户核心诉求为「多设备、零安装」；旧 Python 桌面端不可达此目标。
- **反证条件**：若真机 `getUserMedia` 被浏览器策略/HTTPS 限制无法启用，或 PWA 离线缓存无法满足体积约束 → 需改原生壳或降级为受控安装包。

## D2. 旧 Python 代码只读不移植

- **决策**：`旧版/` 与根目录 Python 工具链保留为一次性测量工具，不移植；`calibration/` 标定工具链保留并继续用于信道验证与回归。
- **依据**：TS 已自实现等价 codec 与仿真器；Python 仅作标定数据来源。
- **反证条件**：若 TS 实现在真实设备上出现与 Python 参考实现不一致的实测偏差且无法自解释 → 需回查 Python 参考。

## D3. ECC：LT 喷泉（外层 rateless）+ RS(255,k) 内层，禁止汉明码

- **决策**：外层 LT 码解决块级擦除/乱序，收够任意 N+1 块即重建；内层 RS(255,223) 解决块内字节错；铁律禁止汉明码。
- **依据**：喷泉码天然免帧同步与重传，契合循环播放收够即停；RS 提供可解析纠错容量界。
- **反证条件**：若真实设备产生大量重复块/块序号碰撞导致 LT 解码不收敛 → 需引入更强喷泉（wirehair）或显式块序号去重。

## D4. 档位：safe=13 / balanced=7 / fast=5，人工选档，发送后全程不变

- **决策**：三档对应最差包络 d_rec≈13（网页自动）、居中、d_rec≈5（网页锁定）。由 `getChannelQuality()` 基于实测 d_rec 推荐，但**人工最终选定且锁定**。
- **依据**：三组实测 σ_PSF = {0.52, 1.03, 2.78}，最差包络决定起步 13px。
- **反证条件**：若某档在所有真实设备上解码成功率 < 目标 99.9% → 该档作废或加严 `RS_PARITY`。

## D5. 音频反馈暂缓，协议帧预留 `feedback_capable` 标志位

- **决策**：本期不实现音频；`protocol.ts` 帧头 bit0 = `feedback_capable`（当前恒 false）；保留 `getChannelQuality()` 供未来回传信道质量/停传信号。
- **依据**：喷泉码收够即停，ARQ 价值被大幅削弱；剩余价值仅为通知停传与回传质量。
- **反证条件**：若实测发现无反馈时发送端无法知道「收够可停」、导致严重冗余或用户困惑 → 需启用音频/屏幕闪烁反馈。

## D6. 符号集最小汉明距离由仿真实测决定，不预设 20bit

- **决策**：`gen_symbols.ts` 在 8×8 二值空间中离线寻优，最大化两两最小汉明距离（当前生成集 minDistance=29）。
- **依据**：任务书明确要求不预设 20bit，以模糊后可达距离为准。
- **反证条件**：若 PSF 模糊后实际可达最小距离 < 阈值（如 <15）→ 需增大 cellPx 或降 symbolBits。

## D7. 屏幕参数：1600×900，PPI 暂按 96（标「假设，待校准」）

- **决策**：PPI=96 仅用于 mm 换算占位，信道仿真以屏幕像素为单位，不受 PPI 影响。
- **依据**：标定报告未确认屏幕 PPI。
- **反证条件**：若标定确认真实 PPI → 更新 `PPI_ASSUMPTION` 并移除「假设」标注。

## D8. colorBits 默认值 = 1（双色：仅亮度+暗）

- **决策**：默认双色；擂台赛同时跑 colorBits=1 与 colorBits=2 对比。若密集校准证明 4 色可行，后续可上调。
- **依据**：最差包络下颜色维度受损严重，双色最稳健；M7 纯颜色方案用密集校准验证 4/8/16 色可行性。
- **更新（摩尔纹模型校准后，见 MODULATION_BAKEOFF §7.8）**：旧摩尔纹模型未建模光学低通，幅度高估约 4×~75×。
  校准后单帧最差包络可达 3bit（8 色）、叠加多帧平均 ×8 可达 6bit（64 色）——**颜色上限确实高于旧结论的 16 色**。
  但单帧最差包络仍不足 4bit，**2bit 仍是最稳默认**；若能保证多帧平均，可上调至 4~5bit。
- **反证条件**：若真实拍摄下 4 色（M7c）格错误率仍 < 1% 且净吞吐更高 → 默认上调至 2。

## D9. 非径向亮度梯度 → 局部归一化 / 密集网格校准

- **决策**：径向暗角模型失效（实测四角 tl=0.252/tr=0.201/bl=0.493/br=0.428，下方更亮）。解码端按区块估计局部增益（dense 模式插值校准格）；颜色判定用「相对距离最小匹配」。
- **依据**：实测四角梯度非径向，全局 CCM/暗角模型已证明失效。
- **反证条件**：若真实设备梯度可被径向模型良好拟合 → 可简化回径向暗角。

## D10. 密集网格校准：每 N×N 插 1 校准格，测试 N=3 与 N=4

- **决策**：N=3 → 开销 ~11%；N=4 → 开销 ~6.25%。校准格用 RGB 区分度大的已知纯色。仿真器在指定位置放校准格→施加亮度场+色偏→读实测值→计算偏移→应用到同区数据格。
- **依据**：用户提出的密集校准思路（任务书 3.1）。擂台赛验证 dense 显著优于 none。
- **反证条件**：若屏幕空间不足无法就近放置可读参考色块 → 回退四角校准或降 colorBits。

## D11. 交织暂不做，等仿真看错误聚簇再定

- **决策**：本期不实现交织；RS 内层 + 喷泉外层已提供两层级容错。
- **依据**：任务书决策 4（交织暂不做）。
- **反证条件**：若真实损伤呈强空间聚簇、RS 单层纠正不足 → 引入网格交织。

## D12. M6（3×3 像素级）判死

- **决策**：cellPx<5 在所有网页端配置下不可行（d_rec≥5），M6 标记为不可行。
- **依据**：三组实测最小 d_rec=5（网页锁定）。
- **反证条件**：若所有设备 PSF σ 实测 < 1（如原生相机级）→ 可重新评估像素级子格。

## D13. safe 档推荐方案 = M1（4bit 符号 + 2 色 + 四角校准）

- **决策**：擂台赛在 web_auto 最差包络下，M1 净吞吐 5.98 bit/格、解码成功率 1.0；M3（4bit+1色+密集）净吞吐 4.42、成功率 0.9999 为次选主力候选。
- **依据**：`MODULATION_BAKEOFF.md` 决策表。
- **反证条件**：若真实拍摄中 M1 的 2 色因色偏大面积误判 → 切 M3 或上调校准密度。

## D14. 摩尔纹建模：加光学低通（OLPF）衰减，幅度由真实照片 FFT 校准

- **决策**：摩尔纹仿真不再是「完美栅格叠加」。合成后叠加等效光学低通：对 fringe 做高斯低通，
  传递函数 `H(f)=exp(-2π²f²σ²)`，参数名 `moiréAttenuationSigma`（单位：格）。
  σ 由 `calibration/calibrate_moire.py` 对 `calibration/photos/` 三张真实照片做 2D FFT 反推：
  实测 native=4.12 / web_locked=6.22 / web_auto=4.19 格，全局默认取中位数 **4.19**。
  另引入 `temporalAveraging`（N=1/4/8）评估多帧平均对摩尔纹的抑制。
- **依据**：旧模型（σ=0）幅度高估约 4×~75×（实测/理想幅度比 H=0.014~0.15，峰/底比 10.9~27.1 证明摩尔纹被真实检出）。
  校准后重跑颜色二分测试：单帧 native 4bit、web_locked 7bit、web_auto 3bit、最差包络 3bit；
  多帧 ×8 后 web_auto 5bit、最差包络 6bit——**颜色上限高于旧结论的 16 色**。
  详见 `MODULATION_BAKEOFF.md` §7.3 / §7.7 / §7.8。
- **假设/局限**：照片中摩尔纹主频（4.4 / 21.3 px）与仿真假定的整帧 `cycles=3` fringe 不同，
  本校准只保证**幅度**匹配，频率仍是唯象假设；每档仅取一张照片。
- **反证条件**：若更多照片/真机实测显示摩尔纹幅度随拍摄距离、屏幕亮度显著变化 → 需按场景分档标定 σ。
