## 二、摩尔纹校准（本期重点，回应你此前的关注）

背景：此前信道仿真用的是「完美栅格叠加」近似，没有光学低通，导致颜色容量被严重高估。本期已补齐：

1. **新增高斯光学低通**：`H(f) = exp(-2π²f²σ²)`，σ 单位 = 格（cell）。
2. `calibration/calibrate_moire.py` 对三组真实标定照片（native / web_auto / web_locked）的均匀块做 **2D FFT**，提取主峰幅度；再用与 `channelSim.ts` **同一套公式 + 同一套 FFT 流程**生成合成块测「理想幅度」，窗增益与亮度加权相消，反推 `H = 实测/理想` 与 σ。
3. **反推结果**：`σ_native=4.12`、`σ_web_auto=4.19`、`σ_web_locked=6.22`（格）。文件缺失时回退默认 σ=4.19。
4. 旧「完美栅格」模型幅度**高估 4×–75×**（与帧率/档位相关）。

5. **颜色二分重跑（核心结论）**：
   - 单帧：native 4 bit / web_auto 3 bit / envelope 3 bit（旧结论单帧仅 2 bit）。
   - 多帧时间平均 ×8：web_auto 5 bit / envelope 6 bit。
   - → 颜色维度**确实高于 16 色**。旧结论卡在 16 色是模型缺陷（缺低通），并非真实的信道上限。
6. **交付物**：`docs/bakeoff_visuals/spectrum_moire_*.svg`（仿真 vs 实测频谱对比图）、报告 §7.3/7.5/7.7/7.8、`DESIGN_DECISIONS.md` D14 + 数值表。
7. **验证**：`tsc --noEmit` 0 错误；20 个单测全过。

## 七、实施进度更新（接收端 + 离线分析脚本，已落地）

按 Q2 要求，接收端纯 TS 实现已全部就绪（不引 OpenCV.js），并补齐离线分析脚本：

- `web/src/receiver/locate.ts`：三锚点检测（白底+居中暗方块判据，排除「白底数据格」误判）→ 旋转判定（0/90/180/270）→ 转正 → 由两邻边外推第 4 角 → 8 参数单应（DLT）透视校正。
- `web/src/receiver/normalize.ts`：**密集校准格局部增益场**（`GainField`），真解校准格（红/绿奇偶两色）后双线性插值到数据格，抵消非径向亮度梯度——是「实解校准格→应用到邻近数据格」的实装，非仿真。
- `web/src/receiver/decoder.ts`：形状 = 8×8 暗点阵对 16 图案汉明最近匹配；颜色 = 增益校正后相对调色板最小距离匹配。
- `web/src/receiver/pipeline.ts` + `viz/raster.ts`（纯 TS 光栅化，与 `screenRender` 对偶）+ `scripts/offline_decode.ts`：**定位→透视校正→逐格解码→与真值比对**，输出**格错误率**（cell error rate，判错的数据格占比；**不是**比特错误率 BER）、错误分布热力图(SVG)、错格清单(JSON)。支持 `--selftest`（合成帧自检）与 `--photos <dir>`（真机照片，按修改时间对应循环序列，自动对齐帧序取最小**格错误率**）。

**一处主动调整（请知悉）**：发送端默认 `colorBits` 由 1 改为 **2**（即 `2 bit (4色)`：红/绿/蓝/白）。原因：原 `colorBits=1` 调色板是「深灰/白」，导致 `colorIdx=0` 时深色底+深色形状几乎不可见、大面积不可解；4 色下形状在任一亮底均可见，也契合你「颜色维度已采纳」的方向。已同步 `SendPage` 演示载荷为共享常量 `DEMO_PAYLOAD`，离线脚本复用同一真值。
