## 3. 本轮关键纠正（务必看）

### 3.1 `cellPx` 到底是什么
**`cellPx` = 数据格（cell）的边长，单位「屏幕像素」，不是符号像素。**
层级：数据格 ÷ 8 = 符号像素。例：safe 档 `cellPx=13` 屏幕像素 → 符号像素 = **1.625 px**。

### 3.2 之前线上渲染是「假密度」
旧发送页把 24×14 的小网格**拉伸铺满视口**（1920×1080 下每格 ≈77px，符号像素 ≈9.6px）。
这能验证「解码机制work」，**但不能验证设计密度**——实际密度只有设计值的约 1/36。
→ 已改为**按真实 `cellPx` 渲染**。

### 3.3 渲染 bug（会让实测完全无效，已修）
`screenRender.ts` / `raster.ts` 画 8×8 符号点阵时用 `fillRect(..., sub-1)`（固定扣 1px 缝隙）：
`sub = cellPx/8`。结果：

| cellPx | 符号像素 sub | 实际点宽 `sub-1` | 后果 |
|---|---|---|---|
| 64（旧默认） | 8 | 7px | 正常 |
| **13（safe）** | 1.625 | **0.625px** | 点比缝窄，符号糊成底色 |
| **8（balanced）** | 1.0 | **0** | 符号消失 |
| **5（fast）** | 0.625 | **负数** | 画不出来 |

（注：`raster.ts` 注释里其实早有人发现「scale<16 时宽度为 0，符号整体消失」，但 `screenRender.ts` 没同步。）
→ 改为**取整边界**渲染（`round(x+gx*sub)` → `round(x+(gx+1)*sub)`，保证每点 ≥1px），两端严格对偶。

## 4. 当前实测实现（全屏真实密度）

- 测试页 `/#/test`：**真实尺寸铺满**模式（默认开），每格正好 `cellPx`，网格按屏放大到 ~1080p：
  - safe(13px) → **147×83** 网格（1911×1079 屏像素）
  - balanced(8px) → **240×135** 网格（1920×1080）
  - fast(5px) → **384×216** 网格（1920×1080）
- 大网格用 **`encodeFile(..., fill:"cycle")` 循环填充**，否则有效载荷小于数据格容量，全屏大部分是空白格。
- 解码端离线脚本 `offline_decode.ts` 用**同一网格 + 同一 scheme + 循环填充**生成真值，逐格比对得**格错误率**（非 BER）+ 错误热力图。支持 `--pattern T1..T8` 指定被测图案。

## 5. 实测方法（给执行方）

1. 电脑开 `https://color-transfer.pages.dev/#/test`，确认停在「真实尺寸铺满」。
2. 手机拍 T1–T8（建议每张连拍多张，覆盖不同距离/角度）。
3. 照片导回电脑某目录，运行：
   ```bash
   cd web
   npx tsx src/scripts/offline_decode.ts --pattern T3 --photos <照片目录>
   ```
4. 看 `calibration/out_offline_decode/cell_error_report.json` 与 `heatmap.svg`：
   - **格错误率**接近 0 → 该编码方式在真机上可行；
   - 某区域错误集中 → 对应屏幕位置有亮度梯度/摩尔纹，需调校准或降档。

> 注：手机端浏览器内实时解码（`/#/test/receive`）本期为骨架占位，正式打分走离线脚本（更可控、可出热力图）。

## 6. 已知限制（影响实测结论，需关注）

1. **fast 档（cellPx=5）形状维度物理不可渲染**：8×8 符号点阵每点仅 0.625 屏幕像素 <1px，符号无法成形。这与仿真中 M5（cellPx5 + 4bit 符号）格错误率 **0.9225** 一致。**T6/T7 的形状维度预期必死**，结论应据此修正 fast 档（提 cellPx 或降 symbolBits）。
2. **RS 仅做擦除纠正**：解码靠置信度标记可疑字节；若未知错误超 16 字节/码字会失败（不静默）。若实测大量「纠正失败」，需降档或加交织。
3. **`sharp` 本地未装**：离线解码脚本依赖 `sharp` 读图，需 `npm install` 装原生模块；CI 内可装。
4. **分辨率假设**：全屏网格按 1920×1080 参考屏设定；非 1080p 屏上图案会有黑边，但每格仍是真实 `cellPx`，不影响密度结论。
