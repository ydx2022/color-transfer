# 光学信道实拍标定 · 拍摄协议

> 目标：用真实手机（华为 Mate50E）拍摄屏幕上显示的标定测试卡，
> 标定「屏幕 → 摄像头」这条光学信道的 5 个参数：
> **ρ**（摄像头像素/屏幕像素）、**PSF**（模糊核）、**σ**（噪声）、**CCM**（色彩串扰矩阵）、**暗角场**。
> 结果写入 `calibration.json`，供后续信道仿真器直接读取——它是决定
> "数据单元能做多大、像素级编码行不行" 的唯一实测依据。

## 0. 流程总览

```
make_chart.py 生成 chart.png + layout.json（严格同源）
    → view_chart.html 全屏 1:1 显示 → 手机专业模式拍摄
    → analyze_calibration.py 分析
    → report.md（人读）+ calibration.json（机器读）+ debug/（肉眼核对）
```

测试卡是**静态 PNG**：布局与像素由脚本一次性确定，不依赖浏览器窗口大小/缩放/dpr，
也杜绝"先全屏再导出、导出后不敢动窗口"的脆弱流程。layout.json 与 PNG 天然一致。

## 1. 生成测试卡（每块屏幕做一次）

```powershell
cd d:\Project\ColorTransfer\calibration
python make_chart.py          # 自动检测主屏设备分辨率（1600x900 屏会得到 chart_1600x900.png）
```

- 屏幕内容 ≥ 全部区域且"布局自检通过：无区域重叠"才算成功；
- 多显示器/想指定尺寸时：`python make_chart.py --width 1600 --height 900`；
- 产出 `charts/chart_<W>x<H>.png` 与 `charts/chart_<W>x<H>.layout.json`。

各区域对应的标定项：

| 区域 | 标定什么 |
|---|---|
| 斜边（5°） | PSF 模糊核 σ、MTF（ISO 12233） |
| 多周期条纹（横+竖） | 对比度曲线 → **临界周期 T_c**（数据单元尺寸下限） |
| 32 级灰阶 | 伽马 γ、黑/白电平、噪声平坦区 |
| 24 个已知 sRGB 色块 | 3×3 CCM 色彩串扰矩阵 |
| 9 份重复图案（中心+四角+四边中点） | 暗角衰减、几何畸变 |
| 四角同心三方块 | 定位标记（透视校正锚点） |
| 顶部白色标尺 | PPI（屏幕像素 ↔ 毫米换算） |

## 2. 屏幕与环境准备

| 项目 | 设置 | 原因 |
|---|---|---|
| 屏幕亮度 | **100%**，关闭自动亮度 | 亮度是灰阶/伽马测量的基准 |
| Windows 夜间模式/护眼模式 | **关闭**（含显示器低蓝光模式） | 会整体偏色，摧毁 CCM |
| Windows HDR | **关闭** | HDR 改变伽马与色域映射 |
| 色彩模式 | **标准/sRGB**（不要"鲜艳"） | 鲜艳模式过饱和，CCM 失真 |
| 通知 | 开启专注助手/勿扰 | 中途弹窗毁照片 |
| 电源 | 插电、关闭"若干分钟后熄屏" | 屏幕必须常亮 |
| 环境光 | **关灯或拉窗帘**；调整屏幕角度直到看不到灯/窗/自己的倒影 | **反光是头号干扰源** |

## 3. 显示测试卡（1:1 像素显示是铁律）

1. 浏览器（Chrome/Edge）打开：
   `view_chart.html?img=charts/chart_1600x900.png`（双击 HTML 后在 URL 加 `?img=`，或先起本地服务器）。
2. 状态栏应显示 **"OK 1:1 完整显示"**——若显示"⚠ 图像大于屏幕"，用 make_chart.py 按屏幕重新生成。
3. 按 **F** 全屏，等 2 秒（浏览器提示气泡消失），**点击状态栏将其隐藏**。
4. **不要用 Windows 照片等看图软件显示拍摄用的 PNG**——它们会"适应窗口"缩放，
   把 1px 条纹插值模糊，摧毁测量。查看器把图像按 1:1 设备像素映射（浏览器缩放也不影响）。

## 4. 相机设置（华为 Mate50E，全程不得改动）

**必须关闭的"优化"（自动锐化/调色会摧毁测量）：**

- ❌ AI 摄影大师　❌ 场景识别　❌ 美颜/滤镜/风格
- ❌ 夜景模式、自动超级微幕　❌ 水印　❌ HDR

**必须锁定（专业模式 PRO）：**

| 参数 | 设置 | 说明 |
|---|---|---|
| ISO | 手动 **100** | 屏幕很亮，足够 |
| 快门 | 手动，从 **1/125** 试拍调起 | 以直方图为准（见下） |
| 对焦 | **MF 手动**，对到屏幕表面 | 放大预览确认最粗条纹锐利 |
| 白平衡 | **手动锁定**（如 5000K） | 锁定后全程不动，否则 CCM 逐张漂移 |
| 变焦 | **1x 主摄，禁止变焦** | 数码变焦破坏 ρ 与分辨率 |
| 格式 | JPG 最高画质 | RAW(DNG) 需转 PNG/TIFF 才能喂脚本 |

**曝光判定（试拍 1~2 张回看直方图）：** 白色块峰值接近但不顶到右墙（≤230），
黑色块不贴死左墙（5~20），两侧都不剪裁时取中间值。

## 5. 现场布置

- **三脚架**（或书堆固定），**3 秒延时**快门，避免手指按压抖动；
- 手机正对屏幕，四边基本平行，测试卡占画面 **85%~95%**（太大四角标记出画 → 分析失败）；
- 拍摄中不碰桌子，每张之间手机绝对不动；
- 屏幕表面灰尘先吹掉。

## 6. 拍摄清单

| # | 内容 | 数量 | 命名 | 说明 |
|---|---|---|---|---|
| A | **全区域测试卡** | **3 张** | `full_1.jpg` `full_2.jpg` `full_3.jpg` | **主数据**；重复 3 张评估可复现性 |
| B | 视频（可选） | 1 段 | `video.mp4` | 专业模式 4K/30 或 1080p/60，锁参数拍 10~20 秒静止测试卡（评估帧间一致性与卷帘快门，脚本后续处理） |

每拍 1 张立即回放：四角定位标记完整、无反光光斑、直方图不剪裁；不满足就重拍。

## 7. 量 PPI（一次性）

用直尺/卡尺量**画面顶部白色标尺线**（两条竖刻度内侧之间）的实际长度，精确到 0.5mm，记下来。
分析时用 `--ppi-mm` 传入（见第 9 节），不填则输出只有"屏幕像素"单位（设计结论本身就以屏幕像素为准，PPI 仅用于毫米换算）。

## 8. 传文件（别在这步毁掉数据）

手机 → 电脑用 **数据线 / 华为手机助手**，选**原图**。
**禁止**微信/QQ/网盘传输——压缩伪影会被当成信道噪声测量。

```
calibration/photos/20260831/

```

（layout.json 已在 charts/ 下，无需复制。）

## 9. 分析命令

```powershell
cd d:\Project\ColorTransfer\calibration
python analyze_calibration.py --layout charts/chart_1600x900.layout.json `
    --photos photos/20260831/full_1.jpg photos/20260831/full_2.jpg photos/20260831/full_3.jpg `
    --ppi-mm 203.5 --outdir out_20260831
```

输出：

- `out_<日期>/report.md` —— 人读报告（ρ/σ_PSF/T_c/γ/CCM/暗角/噪声 + **设计结论**：数据单元最小尺寸、像素级编码是否可行）
- `out_<日期>/calibration.json` —— 机器读，直接喂给信道仿真器
- `out_<日期>/debug/<照片名>/` —— 每步测量的可视化校验图

## 10. 结果核对清单（防"静默失效"，**务必肉眼核对**）

旧项目正是被"看起来在跑、其实测错了"的模块骗了很久，所以：

1. `debug/<照片>/00_fiducials_try0.png` —— 4 个红点是否都套在定位标记**正中心**？
2. `02_all_regions.png` —— 每个红框是否都套在对应图案上？
3. `03_edge_fit.png` —— 绿色拟合线是否贴合斜边？
4. `report.md` 第 8 节「可复现性」—— 3 张照片各项相对标准差 < 2% 视为可信；
5. 任一照片 `status` 不是 ok → 打开对应 debug 图找原因（多为遮挡、反光、四角出画）。

## 11. 网页端信道标定（capture_test.html）

### 为什么要单独标定网页端

ColorTransfer 的解码端最终跑在**手机浏览器**里（`getUserMedia`）。浏览器出于安全限制：

- **永远拿不到 Bayer 原始 sensor 数据（RAW）**，只能拿到 ISP 处理过的 YUV / JPEG / 视频流；
- **锁定 ISO / 快门 / 白平衡的约束在移动端基本不可用**（iOS Safari 仅支持 `torch`、分辨率、前后摄等极少量项）。

所以自动白平衡、自动曝光、tone mapping、锐化是**信道的固有部分**——关不掉，也不该被当成"没拍好"。本节标定的就是这条真实信道。

### 步骤

1. **起 HTTPS 服务**（手机浏览器只在安全上下文开放摄像头）：

   双击 `start_capture_server.bat`，或命令行：

   ```powershell
   python serve_https.py --port 8443
   ```

   窗口会打印当前局域网地址，并**自动生成/更新 `capture_qr.png`**（手机扫码即可，避免手输 URL）。

   注意：**局域网 IP 可能因 DHCP 变化**（如 192.168.0.5 → 192.168.0.6），每次启动以窗口显示的地址为准，旧二维码会随之失效。手机连不上时检查 Windows 防火墙是否允许 Python 入站。

2. **电脑端显示测试卡**：浏览器打开 `https://localhost:8443/view_chart.html`，信任自签证书，按 **F 全屏**。

3. **手机端拍摄**：手机连同一 WiFi，打开 `https://<电脑IP>:8443/capture_test.html`

   - Chrome / Edge 首次警告证书 → 点「高级」→「继续前往」
   - 「① 启动摄像头」后先看**能力探测表**：哪些参数可锁一目了然
   - 「② 连续捕获」默认 5 张 / 间隔 1000ms（用于评估自动白平衡与曝光的**时间漂移**）
   - 盯住直方图：**两侧不撞墙**（过曝/欠曝 < 1%），否则灰阶与 γ 测量作废

4. **下载**：「③ 打包下载 (ZIP/PNG)」。包内是**无损 PNG**（避免 JPEG 压缩污染噪声测量），并附 `capture_info.txt`（实际分辨率、`getCapabilities()` / `getSettings()`、UA、曝光统计）。

5. **分析**：

   ```powershell
   # 把 PNG 解到 photos/web/
   python analyze_calibration.py --layout charts/chart_1600x900.layout.json `
       --photos photos/web/*.png --outdir out_web
   ```

### 与原生相机数据的差异

网页端视频流分辨率通常**远低于**原生相机（常见 1920×1080 甚至 1280×720），因此 ρ 会明显变小、采样约束变紧；且自动处理更激进，噪声与色彩漂移更大。故网页端结论应比原生相机数据**更保守**。

## 12. 常见问题

| 症状 | 原因与处理 |
|---|---|
| "未找到 4 个定位标记" | 四角出画或反光淹没 → 拉远/避反光重拍；先看 debug 图 |
| γ / 暗角逐张漂移 | 白平衡或亮度没锁死；自动亮度被触发 |
| 条纹区摩尔纹很重 | **正常**——摩尔纹正是 T_c 的测量对象，别为消除它改对焦 |
| ρ 小于 0.3 | 拉太远，无谓损失分辨率 → 靠近重拍 |
| ρ 大于 1.5 | 屏幕没填满画面 → 靠近重拍 |
| 噪声 σ 异常大 | ISO 被自动抬高 / 图片经微信传输被压缩 / 快门过长手抖 |
